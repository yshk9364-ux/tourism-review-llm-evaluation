# 旅游评论大模型数据标注与评测

英文仓库名：`tourism-review-llm-evaluation`

一个面向 AI 数据标注与大模型评测岗位的学习型项目。项目使用 40 条**模拟中文旅游景区评论**，比较两版 Prompt 在情感分类、问题类型识别、证据提取和人工复核判断上的输出，并通过 Python 自动生成指标与 Bad Case。

> **真实性说明：本项目为个人 AI 数据评测实践项目，使用 40 条模拟旅游评论演示数据标注、Prompt 迭代、自动评测和 Bad Case 分析流程。当前参考标签及模型输出由 AI 工具辅助生成，尚未完成逐条人工复核，相关指标仅用于展示评测流程，不代表真实模型业务效果。**

> `data/gold_dataset.csv` 是待人工复核的金标准草稿，`reviewed_by_human` 均为“否”。不能将 AI 草稿直接作为人工标注结果或对外性能结论。

## 项目背景与业务问题

旅游评论中既有“景色很美”这样的清晰反馈，也有反讽、正负混合和信息不足的表达。如果标签不统一，后续分析会失真；如果只看模型总体准确率，也容易忽略模型为什么出错。本项目练习将评论转为可检查的结构化数据，并用可复现脚本评估 Prompt 优化是否改善输出。

## 项目流程

```text
模拟原始评论 → 草稿金标准与标注规范 → Prompt V1 / V2 输出
                                      ↓
                     数据检查 → 自动评测 → Bad Case 分析 → 人工复核
```

## 标签体系

| 字段 | 说明 |
| --- | --- |
| sentiment | 正面、 中性、负面 |
| issue_category | 服务、排队、价格、卫生、餐饮、交通、设施、景色、宣传、其他、无明显问题；可多标签，以 `;` 分隔 |
| evidence | 必须可在原评论中直接找到的原文片段 |
| need_review | 反讽、模糊、混合情感、二手信息等需要人工复核时为“是” |

## Prompt 迭代

- **V1**：只给出任务要求和五个输出字段，作为基础版本。
- **V2**：补充标签定义、多标签规则、原文证据约束、禁止补充信息、反讽/模糊规则、固定 CSV 格式和两个 Few-shot 示例。

## 实际结果

下表由仓库内的 `scripts/evaluate.py` 对当前 40 条模拟数据实际计算，是**小样本演示结果**。模型输出由 AI 工具辅助生成；V2 与参考标签可能存在同源生成和数据泄漏风险，因此结果不应被包装为模型真实能力或真实业务效果。

| 指标 | V1 | V2 |
| --- | ---: | ---: |
| 情感分类准确率 | 67.5% | 100.0% |
| 问题类型完全匹配率 | 40.0% | 95.0% |
| 问题类型标签级 F1 | 75.0% | 98.4% |
| 证据可定位率 | 100.0% | 100.0% |

V2 的主要改善是减少多标签漏标，并更好处理反讽与正负混合；仍有 R019 的标签边界问题，见 `evaluation/bad_cases.csv`。

## Bad Case 示例

| 评论 | V1 的问题 | V2 的处理 |
| --- | --- | --- |
| “真贴心，排队一个半小时还不让坐” | 按字面判为正面，漏服务标签 | 识别为反讽，判负面并要求人工复核 |
| “玩具旧了一些，但工作人员会主动帮忙” | 只保留正面服务信息 | 保留设施和服务，整体标中性 |
| “学生票到底要不要预约？页面写得不清楚” | 漏价格主题且未复核 | 复核判断正确，但仍漏价格主题，需人工裁决 |

## 项目结构

```text
tourism-review-llm-evaluation/
├── data/          # 模拟原始评论、草稿金标准、两版模型输出
├── guidelines/    # 人工标注规则与质检清单
├── prompts/       # Prompt V1 与 V2
├── scripts/       # pandas 数据检查和评测脚本
├── evaluation/    # 实际指标、自动导出的 Bad Case、评测报告
└── docs/          # 零基础项目讲解和简历材料
```

## 核心能力

- 编写旅游评论标签体系、边界规则和人工质检清单。
- 设计并对比基础版与规则增强版 Prompt。
- 使用 pandas 检查数据完整性、标签合法性与输出覆盖率。
- 计算准确率、标签级 Precision/Recall/F1，自动导出 Bad Case。
- 基于错误类型解释 Prompt 改进效果，并保留人工审核边界。

## 运行方法

建议 Python 3.9+，所有 CSV 以 UTF-8 编码保存。

```bash
python3 -m pip install -r requirements.txt
python3 scripts/validate_data.py
python3 scripts/evaluate.py
```

运行后会更新：

- `evaluation/metrics.csv`
- `evaluation/bad_cases.csv`

## 项目局限

- 数据为模拟数据，样本量仅 40 条；没有真实平台数据、用户量或线上效果。
- 待人工复核的金标准草稿尚未完成项目作者的人审，不能作为最终结论。
- 模型输出由 AI 工具辅助生成，且没有接入线上 API 或比较多个真实模型。
- V2 与参考标签可能存在同源生成和数据泄漏风险。
- 未计算多标注者一致性；后续可加入双人标注、裁决记录和更大规模盲测集。
