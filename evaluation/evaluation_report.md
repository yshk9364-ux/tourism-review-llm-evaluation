# 旅游评论大模型数据标注与评测报告

## 1. 项目背景

本项目围绕旅游景区评论场景，比较两版 Prompt 在情感分类、问题类型识别、证据提取和复核判断上的表现。项目将非结构化中文评论转化为可检查的结构化字段，并用 Python 自动计算指标、导出 Bad Case，形成一套可复现的离线评测流程。

## 2. 数据集说明

- 样本量：1,000 条不重复的中文旅游评论。
- 数据来源：项目内自建测试数据，未采集或声称来自任何真实平台；保留了最初的 40 条案例，并以固定模板扩展 960 条可复现样本。
- 覆盖主题：服务、排队、价格、卫生、餐饮、交通、设施、景色、宣传、其他和无明显问题。
- 覆盖难点：正面、负面、中性、正负混合、反讽、多问题与信息不足。
- `gold_dataset.csv` 是当前离线对比使用的基准标签集，`reviewed_by_human` 字段用于记录逐条人工审核状态。

## 3. 标签体系

情感标签为 `正面`、`中性`、`负面`。问题类型可多选，使用英文分号连接：`服务`、`排队`、`价格`、`卫生`、`餐饮`、`交通`、`设施`、`景色`、`宣传`、`其他`、`无明显问题`。证据必须来自评论原文；反讽、模糊、二手转述和正负难分的评论应标记人工复核。

## 4. Prompt V1 与 V2 的区别

| 维度 | V1 基础版 | V2 规则增强版 |
| --- | --- | --- |
| 标签解释 | 仅给出任务字段 | 给出情感和问题标签定义 |
| 多标签 | 未明确 | 要求保留所有独立主题、使用 `;` |
| 证据 | 仅要求提取 | 明确必须是连续原文，禁止补充 |
| 难例 | 无特别规则 | 规定反讽、模糊、混合情感的处理 |
| 输出 | 字段清单 | 固定 CSV 顺序与两个 Few-shot 示例 |

## 5. 评测指标定义

- **情感分类准确率**：情感预测正确的评论数 / 全部评论数。
- **问题类型完全匹配率**：一条评论预测的整组标签与基准标签集完全一致的比例。
- **标签级 Precision**：预测出的标签中，正确标签的比例。
- **标签级 Recall**：基准标签集中的标签被模型找出的比例。
- **标签级 F1**：Precision 与 Recall 的调和平均数。
- **证据可定位率**：预测 evidence 能作为连续片段在原评论中找到的比例。
- **输出完整率**：5 个要求字段均非空的比例。
- **need_review 准确率**：复核判断与基准标签集一致的比例。

| 指标 | V1 | V2 | 变化 |

## 7. Bad Case 分析

`bad_cases.csv` 自动导出 446 条字段不一致记录，其中 V1 为 434 条、V2 为 12 条。以下选择 5 个有代表性的案例：

| review_id | 版本 | 现象 | 分析 |
| --- | --- | --- | --- |
| R0061 | V1 | 将“真有效率”按字面判为正面，只保留服务标签。 | 后半句“晒了半小时”“再等等”构成反讽和排队投诉；V2 通过反讽规则与多标签要求避免了这类遗漏。 |
| R0059 | V1 | 只识别“景色很好”，忽略垃圾和清扫不及时。 | 正负混合评论需要同时保留景色、卫生、服务三个主题，并将总体情感判为中性。 |
| R0062 | V1 | 将未实际到访的转述评论归为“无明显问题”，且未要求复核。 | “没有实际去过”说明信息不足，应保留其他标签并标记 `need_review=是`。 |
| R019 | V2 | 识别页面说明不清，但漏掉学生票预约对应的价格主题。 | 规则增强后仍可能出现隐含主题映射遗漏；这类标签边界需要结合标注规范复核。 |
| R0233 | V2 | 情感和问题类型正确，但 evidence 写成原文不存在的“体验很好”。 | 证据字段必须逐字来自原评论；可通过输出后字符串定位检查发现此类错误。 |

## 8. Prompt 优化前后的变化

V2 的提升主要来自三个约束：一是定义多标签规则，显著减少问题漏标；二是增加反讽与混合情感规则，降低字面化情感误判；三是以固定输出格式、证据约束和 Few-shot 示例稳定字段填写。最明显的变化是问题类型完全匹配率从 61.6% 提升至 99.8%，标签级 Recall 从 69.3% 提升至 99.9%。

## 9. 模型仍然存在的问题

- V2 仍有 12 条字段不一致记录，集中于隐含主题映射、情感边界、证据原文一致性与复核判断。
- 证据可以在原文定位，不等于它覆盖了全部标签；后续可增加“证据覆盖度”的人工抽检。
- 模板扩展提高了测试数量和覆盖面，也可能带来表达模式重复，不能替代真实业务分布下的独立评测。

## 10. 人工审核的必要性

自动化输出适合提升首轮整理和批量比较效率，但不能同时生成参考标签并直接证明自身正确。用于正式人工评测前，应由项目作者按规范逐条核对；复杂条目可由第二位标注者抽检并记录裁决。当前指标是对项目基准标签集的离线对比。

## 11. 项目局限性

本项目使用自建测试数据，1,000 条样本中包含固定模板扩展；基准标签仍需逐条人工审核，且模型输出不是独立线上模型调用日志。项目没有标注者一致性统计或按真实景区、时间分层抽样，因此指标仅适用于当前离线评测配置，不外推为真实旅游业务效果。

## 12. 多模态扩展方向

后续可增加游客图片、短视频和语音评论：图片可标注垃圾、排队长度、设施破损；视频可评测景色真实性与导览信息；再将图文证据对齐，分别计算文本、视觉和跨模态一致性。扩展前需要取得合法数据授权，并建立更清晰的标注规范与隐私处理流程。
