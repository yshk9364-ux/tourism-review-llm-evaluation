01 · PROJECT BACKGROUND

项目背景

旅游评论包含真实体验线索，却往往以口语、反讽和多主题叙述的方式出现。要让模型输出可以比较，首先需要把自然语言变成结构化、可追溯的数据。

场景选择围绕服务、排队、卫生、景色等高频旅游体验主题设计测试评论。

核心问题统一情感、问题类型与原文证据的判断口径，让复杂表达能够进入评测流程。

项目交付形成基准标签集、Prompt、校验脚本、指标结果和 Bad Case 报告。

04 · PROMPT ITERATION

让规则更接近真实评论

07 · BAD CASE ANALYSIS

错误不是终点，
而是下一版规则的起点

01 / IRONY

反讽误判

“真贴心”表面是赞美，却与漫长排队、暴晒事实相矛盾。V2 增加反讽规则，要求结合完整语境判断。

仍需复核：口语表达的讽刺强度可能存在分歧。
02 / MULTI-LABEL

多问题漏标

宣传信息不符与设施维修同时出现。V1 只保留显眼主题；V2 要求提取每个独立问题。

仍需复核：边界标签应持续结合规范检查。
03 / MIXED SENTIMENT

正负混合判断

工作人员主动帮助与设施陈旧并存。V2 保留两类信息，并以整体语义判断为中性。

仍需复核：复杂体验的情感强弱需要人工抽检。
