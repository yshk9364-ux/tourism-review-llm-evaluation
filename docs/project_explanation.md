# 零基础项目讲解：旅游评论大模型数据标注与评测

## 什么是人工标准答案

人工标准答案（也叫金标准）应由人工按照同一份规则逐条审核后得到。本项目的 `gold_dataset.csv` 用作离线对比的基准标签集；`reviewed_by_human` 字段保留了每条记录的人工审核状态。若要将它用于正式人工评测，应先按标注规范逐条核验并更新该字段。

## 什么是 Prompt V1 和 V2

Prompt 是给模型的任务说明。V1 只说“请做分类并输出字段”，它容易漏掉评论里的第二个问题，也可能把反讽按字面理解。V2 增加了标签定义、多标签规则、证据必须来自原文、反讽规则、模糊规则、固定格式和示例。两版的差异让我们可以观察“说清楚规则”是否有帮助。

## 准确率、Precision、Recall 和 F1 是什么

- **准确率**：例如 1000 条情感中有 867 条猜对，准确率就是 86.7%。
- **Precision（精确率）**：模型说“这里有卫生问题”的次数中，真正有卫生问题的比例。它关注“模型说出来的对不对”。
- **Recall（召回率）**：人工答案里所有卫生问题中，模型找出来的比例。它关注“模型漏了多少”。
- **F1**：把 Precision 和 Recall 合在一起看的平衡分数。两者之一很低，F1 就不会高。

本项目问题类型是多标签，因此指标按单个标签累计计算；“完全匹配率”则要求一条评论的整个标签组合都正确，标准更严格。

## 什么是 Bad Case

Bad Case 是模型输出与基准标签集不一致、或证据不能在原文定位的样本。只看平均分数不知道模型哪里会错；看 Bad Case 才能发现，例如 V1 对反讽误判、对混合评论漏标签。`bad_cases.csv` 还会给出“情感误判”“问题漏标”等错误类型，方便复查。

## 为什么不能让 AI 同时生成标准答案并直接证明自己正确

如果同一套自动化规则既生成对照标签又直接证明自己正确，结果可能只是“和自己一致”，不代表真的正确。还可能把遗漏的主题一起写进对照标签，导致错误没有被发现。更可靠的做法是：先按规范建立基准标签集，再由人工对复杂样本抽检，分歧留下裁决记录。

## 面试时如何诚实介绍

可以说：这是一个基于 1000 条自建旅游评论测试数据的离线评测项目，围绕标签体系、Prompt 迭代、数据质检和 Bad Case 分析展开。我用 pandas 编写了数据生成、检查和评测脚本，并对比两版结构化输出。要主动说明数据不来自真实平台，当前指标对应项目内的离线基准标签集，不外推为线上业务效果。这样的介绍既清楚，也符合项目实际范围。
