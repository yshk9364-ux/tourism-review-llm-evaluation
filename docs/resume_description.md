# 求职材料：旅游评论大模型数据标注与评测

## 简历项目名称

旅游评论大模型数据标注与评测

## 三条简历项目经历

- 构建1000条自建旅游评论测试集与情感、问题类型、证据、复核标签体系，覆盖反讽与多问题场景。
- 编写两版 Prompt，对比基础指令与规则增强指令在结构化旅游评论标注任务中的差异。
- 使用 pandas 完成 CSV 质检、指标计算与 Bad Case 导出；当前自建测试集对比中 V2 标签级 F1 为99.9%。

## 约150字项目介绍

围绕旅游景区评论，完成了一项离线数据标注与大模型评测项目。我构建并管理1000条自建测试评论，设计情感、问题类型、原文证据和复核标签规则，并建立项目基准标签集。随后以两版 Prompt 生成结构化输出，使用 pandas 检查字段、重复 ID、标签合法性和覆盖率，计算情感准确率、多标签 Precision/Recall/F1 等指标，并自动导出 Bad Case。当前结果基于自建测试数据和项目内基准标签集，用于比较 Prompt 规则对离线评测结果的影响。

## 60 秒面试介绍

我做过一个旅游评论大模型数据标注与评测项目。项目包含1000条自建测试评论，覆盖服务、排队、价格、卫生等主题，也包含反讽、正负混合和信息不足等难例。我先制定标注规范和基准标签集，再设计基础版与规则增强版 Prompt，并用 pandas 编写数据检查和评测脚本。当前离线对比中，V2 的问题类型标签级 F1 从 V1 的80.5%提升到99.9%，主要来自多标签漏标、反讽和证据抽取错误的减少。数据为项目内自建测试数据，指标用于说明评测方法和复盘过程。

## 面试官可能询问的问题与参考回答

1. **这个项目的数据来自哪里？**  
   全部是我为练习设计的模拟评论，不来自真实平台，也没有声称为真实用户数据。

2. **为什么要做两版 Prompt？**  
   为了把“任务描述不够具体”变成可比较的实验：V2 增加标签定义、多标签、反讽和证据规则，观察这些约束对结果的影响。

3. **gold_dataset 在项目中起什么作用？**
   它是当前离线对比使用的基准标签集，包含情感、问题类型、证据和复核判断。`reviewed_by_human` 用于记录后续逐条审核状态；正式人工评测前应按规范完成核验。

4. **V2 为什么比 V1 好？**  
   当前小样本离线演示中，V2 让模型保留多个主题、处理反讽并标记复核，因此标签级 Recall 和 F1 提升明显；这不等于真实模型能力。

5. **什么是问题类型完全匹配率？**  
   它要求一条评论的整组标签完全一致。例如人工是“卫生;景色”，模型只写“景色”仍算不完全匹配。

6. **为什么 F1 比准确率更适合多标签？**  
   多标签任务容易出现“部分正确”。F1 结合 Precision 和 Recall，能反映模型是否漏掉标签或乱加标签。

7. **如何检查模型证据？**  
   脚本检查预测 evidence 是否是评论原文的连续片段；但是否覆盖全部主题，还需要人工抽检。

8. **最典型的 Bad Case 是什么？**  
   V1 将“真贴心，十分钟没人理”按字面判正面。V2 增加反讽规则后能依据实际不满事实判负面。

9. **如果扩展到真实项目，你会先做什么？**  
   先确认数据授权与脱敏，再抽样建立双人标注和裁决流程，划分独立测试集，最后才比较不同模型和 Prompt。

10. **这个项目有什么局限？**  
    样本为1000条自建测试数据，未计算标注者一致性，也没有独立线上调用日志；结果适用于当前离线标签集上的 Prompt 对比，不外推为线上业务效果。
