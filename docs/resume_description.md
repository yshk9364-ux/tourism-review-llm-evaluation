# 求职材料：旅游评论大模型数据标注与评测

## 简历项目名称

旅游评论大模型数据标注与评测（模拟数据离线项目）

## 三条简历项目经历

- 设计40条模拟旅游评论及情感、问题类型、证据、复核标签草稿，覆盖反讽与多问题场景。
- 编写两版 Prompt，对比基础指令与规则增强指令在结构化旅游评论标注任务中的差异。
- 使用 pandas 完成 CSV 质检、指标计算与 Bad Case 导出；小样本演示中 V2 标签级 F1 为98.4%（草稿参考标签对比）。

## 约150字项目介绍

围绕旅游景区评论，完成了一个小规模离线数据标注与大模型评测练习项目。我设计40条模拟评论，建立情感、问题类型、原文证据和人工复核标签规则，并准备待人工复核的金标准草稿。随后用两版 Prompt 生成 AI 辅助输出，使用 pandas 检查字段、重复 ID、标签合法性和覆盖率，计算情感准确率、多标签 Precision/Recall/F1 等指标，并自动导出 Bad Case。当前小样本演示结果仅基于模拟数据与草稿参考标签，且可能存在同源生成风险，不能代表真实线上模型表现。

## 60 秒面试介绍

我做过一个旅游评论大模型数据标注与评测的离线练习项目。项目里有40条我设计的模拟评论，覆盖服务、排队、价格、卫生等主题，也包含反讽、正负混合和信息不足的难例。我先写了标注规范和待人工复核的金标准草稿，再设计基础版与规则增强版 Prompt，并用 pandas 编写数据检查和评测脚本。当前小样本演示中，V2 的问题类型标签级 F1 从 V1 的75.0%提升到98.4%，主要是减少了多标签漏标和反讽误判。我会明确说明：数据和输出均为模拟/AI 辅助，草稿标签还要逐条人工审核，且存在同源生成风险；这个项目展示的是我的评测流程和复盘能力。

## 面试官可能询问的问题与参考回答

1. **这个项目的数据来自哪里？**  
   全部是我为练习设计的模拟评论，不来自真实平台，也没有声称为真实用户数据。

2. **为什么要做两版 Prompt？**  
   为了把“任务描述不够具体”变成可比较的实验：V2 增加标签定义、多标签、反讽和证据规则，观察这些约束对结果的影响。

3. **gold_dataset 为什么说是草稿？**  
   当前标签由 AI 辅助生成，作者尚未逐条签核，只能视为待人工复核的金标准草稿。下一步是按规范逐条审核并更新 `reviewed_by_human`。

4. **V2 为什么比 V1 好？**  
   当前小样本离线演示中，V2 让模型保留多个主题、处理反讽并标记复核，因此标签级 Recall 和 F1 提升明显；这不等于真实模型能力。

5. **什么是问题类型完全匹配率？**  
   它要求一条评论的整组标签完全一致。例如人工是“卫生;景色”，模型只写“景色”仍算不完全匹配。

6. **为什么 F1 比准确率更适合多标签？**  
   多标签任务容易出现“部分正确”。F1 结合 Precision 和 Recall，能反映模型是否漏掉标签或乱加标签。

7. **如何检查模型证据？**  
   脚本检查预测 evidence 是否是评论原文的连续片段；但是否覆盖全部主题，还需要人工抽检。

8. **最典型的 Bad Case 是什么？**  
   V1 将“真贴心，十分钟没人理”按字面判正面。V2 增加反讽规则后能依据实际不满事实判负面。

9. **如果扩展到真实项目，你会先做什么？**  
   先确认数据授权与脱敏，再抽样建立双人标注和裁决流程，划分独立测试集，最后才比较不同模型和 Prompt。

10. **这个项目有什么局限？**  
    样本只有40条且为模拟数据，输出由 AI 辅助生成，未计算标注者一致性，也没有独立线上调用日志；V2 与草稿参考标签可能同源，存在数据泄漏风险。
